# W3.1 — GDC ingest and normalisation

**Owner:** W3 · **Week:** 1 · **Branch:** `w3/tcga-gdc-ingest`

What was decided and why. The code is in [`src/bulk/`](../../src/bulk/); this is
the record of the choices it encodes, so a reader does not have to reconstruct
them from the source.

---

## 1. W3 built the shared gene index, because the fallback fired

[Open decision #2](../../docs/open_decisions.md) says W1 emits
`config/gene_index/gene_index_1.0.0.txt` in week 1 and W3 conforms — with a
written fallback: *"If W1's ingest slips, W3 emits a provisional index from the
GDC gene model and W1 conforms."*

W1's week-1 work landed (ingest guards, per-batch QC, ambient estimator, labels)
and `config/gene_index/` still contains only its README. `grep -r 'ENSG' src/`
returns nothing: W1's pipeline is entirely symbol-keyed. So the fallback has
fired and W3 built it.

**The artifact is versioned `0.9.0`, not `1.0.0`, deliberately.** Provisional,
W3-built, superseded the moment W1 emits theirs. Promoting it to 1.0.0 is a
week-1 meeting decision, not a side effect of this branch.

## 2. The key is the unversioned Ensembl ID

[Open decision #3](../../docs/open_decisions.md)'s recommendation, adopted.
TCGA STAR counts arrive as `ENSG00000160182.3`; a single-cell reference built on
a different GENCODE release carries a different suffix for the same gene.
Joining on the versioned string drops those genes silently — the ~8% loss the
decision warns about. The version is stripped into its own column and the join
key is the bare `ENSG`.

Symbols are a mapped column, never a key. Every panel lookup resolves through
`gene_index_0.9.0.map.tsv`.

## 3. The index contains panel genes. This is the one thing not to "fix"

`build_signature()` refuses to run if a target gene is in the index it is handed
([`signature.py:96`](../../src/reference/signature.py#L96), pinned by
[`test_leakage.py:45`](../../tests/test_leakage.py#L45)). W3's bulk matrix must
carry GUCA2A and CDX2 — they are the **outcome variables** for the week-2
premise check and for the Stage 4 variance question.

Both hold at once: the committed index carries every gene, and W1 passes a
filtered view via `target_free_index()`. Invariant 2 binds at the point where it
matters — the reference matrix — without amputating the shared index for the arm
whose deliverable needs those genes.

> **Removing panel genes from the index itself would make W3's own deliverable
> unrepresentable on the shared index.** Raised as
> [open decision #12](../../docs/open_decisions.md).

## 4. Filtering rules, applied and counted

No expression threshold and no biotype restriction at ingest. A threshold baked
into a matrix is invisible downstream; it belongs at signature construction,
where W1 and W2 can see it. `build_gene_index(keep_biotypes=...)` exists so the
choice is explicit rather than unavailable.

| Rule | Decision |
|---|---|
| GENCODE `_PAR_Y` duplicates | Dropped. Deterministic, and what makes ENSG unique. |
| chrY | Retained in the matrix; must be barred from any signature — sex is a locked covariate, so a chrY gene in a signature leaks sex into the fraction estimate. |
| Duplicate symbols | Never collapsed. One row per ENSG, `symbol_ambiguous` flagged. Collapsing fabricates a gene; dropping loses signal. |
| Ambiguous panel symbols | **Not** auto-resolved. A panel gene mapping to two ENSGs is a decision, not a tie-break. Eleven genes in tiers A–D; pin them by hand. |

Losses are counted at every step and written to
`results/<date>_<sha>/tcga_gene_index_filtering.parquet`.

## 5. Both scales, and a guard at every entry point

TPM (linear, for deconvolution) and log2(CPM + 1) (for survival) in separately
named files. `src/bulk/normalise.py` asserts the scale at every entry *and*
exit — `assert_linear_scale`, `assert_log_scale`, `assert_tpm`, `assert_counts`.
A test checks the two guards are not both satisfiable, because if they were,
neither would mean anything.

**The prior count is 1.0**, stated because "log-CPM" names a family and the
offset changes the numbers. It keeps zeros at exactly 0.0.

**TPM is GDC's `tpm_unstranded`, rescaled — not recomputed.** GDC computes TPM
over the full gene set, so subsetting to the shared index leaves rows that no
longer sum to 1e6 and samples that are no longer comparable. Rescaling is
*correct* without gene lengths, because TPM is already length-normalised.
Recomputing from counts would need the effective lengths GDC used, which are not
published with the counts; guessing them introduces a discrepancy nobody could
later diagnose. `assert_tpm` catches an un-renormalised subset.

## 6. One aliquot per (patient, sample type)

Some patients have several sequenced aliquots. Leaving them in double-weights
those patients, and the patient is the unit of inference (invariant 5).

**Rule:** earliest vial, then lowest plate, then lexicographically smallest
barcode. Arbitrary but deterministic, and it *does not look at expression* — a
rule preferring the highest-depth aliquot would let the data choose the sample.

Sample types 01 (primary tumour) and 11 (normal-adjacent) are in scope; 02, 05
and 06 are counted and excluded, never silently dropped.

## 7. COAD and READ go into one matrix with a `project` column

[Open decision #4](../../docs/open_decisions.md) (pool or stratify) is **not**
decided here. One matrix with a project column keeps it open; two files would
pre-decide it in the file layout. W3.2 reports the premise check stratified by
project regardless, which is input to that decision.

## 8. Technical factors come from the barcode

TSS, plate, sequencing centre, analyte and vial are not in any metadata file —
they are encoded in the aliquot barcode. W3.4 cannot test confounding without
them, so `parse_barcode()` is strict: anything that is not a full 28-character
aliquot barcode raises. A wrong-but-plausible parse would read as *"plate is not
confounded with stage"*, which is the worst available failure.

## Status and what is not done

The modules are written and unit-tested; **the tests have not been executed** —
there is no Python interpreter on this machine, so `env/w3_bulk.yml` has never
been created here. Nothing has been downloaded from the GDC and no matrix
exists yet. Before this branch merges someone must run:

```bash
conda env create -f env/w3_bulk.yml && conda activate brp-w3
pip install -e ".[dev]"
pytest tests/test_bulk_ingest.py && ruff check src tests
python -m src.bulk.ingest query
python -m src.bulk.ingest download --limit 5     # smoke test
python -m src.bulk.ingest gene-index
python -m src.bulk.ingest build
```

The **portal reconciliation is the acceptance test** and it has not been run.
`reconcile_counts()` prints samples and patients by project and sample type;
compare against the GDC portal's own facet counts by eye and record the
comparison here. A silent shortfall of forty samples is invisible in a matrix
and fatal in a survival model.

Expect roughly 620 patients across COAD and READ
([execution_plan.md:278](../../execution_plan.md#L278)). If the reconciliation
lands far from that, stop and find out why before building anything on it.
